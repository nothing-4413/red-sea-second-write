# 架构边界与主流程

本 Demo 沿用一测的架构设计线：Unity 2022.3 LTS + C#，Core 规则可脱离场景运行，表现层只提交命令和消费事件。

## 源码边界

| 模块 | 目录/类型 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 数据模型 | `Core/Match3Core.cs` 中的 `BoardModel`、`Piece`、`Obstacle`、`CellPos` | 保存逻辑状态、快照、恢复 | 访问 Unity 场景或动画 |
| 规则 | `MatchFinder`、`SwapValidator`、`MvpRulePipeline`、`GravitySystem` | 匹配、交换、消除、障碍物、重力、补充 | 读写 `GameObject` |
| 事件 | `Architecture/EventQueue.cs`、`ResolveEvent` | FIFO 排队、上限保护 | 推导规则或修改棋盘 |
| 回合编排 | `Architecture/TurnResolver.cs`、`Flow/TurnStateMachine.cs` | 串联命令、规则、事件、目标、回放 | 绘制 UI |
| 目标/计分 | `Architecture/GoalSystem.cs` | 只读 `ResolveSummary` 和模型结果 | 扫描 View |
| 回放 | `Architecture/ReplayRecord.cs` | 保存规则版本、seed、输入、摘要 | 保存动画状态 |
| 配置 | `Config/LevelConfigAsset.cs` | ScriptableObject → Core 配置 | 把参数散落在表现脚本 |
| 表现 | `Presentation/BoardView.cs`、`Match3DemoController.cs` | 读取模型、消费 FIFO、提交命令 | 直接写 `BoardModel` |

## 主流程

```text
点击输入
  -> TurnStateMachine.Selecting
  -> TurnResolver.SubmitSwap
  -> SwapValidator
  -> MvpRulePipeline
  -> EventQueue(FIFO)
  -> BoardView/EffectPlayer 消费事件
  -> ResolveSummary
  -> GoalSystem + ScoreSystem
  -> Idle / Win / Lose
```

一次操作在 `Resolving/Animating/Refilling/CheckingChain` 期间锁定输入。无效交换直接返回，不写入步数、随机流、回放或目标进度。

## 扩展示例：新增冰块障碍物

1. 在 `ObstacleType` 追加 `Ice`，不调整已有枚举顺序。
2. 在 `LevelConfigAsset` 增加冰块耐久配置并转换为 `ObstacleDefinition`。
3. 在 `MvpRulePipeline` 的障碍物伤害策略中增加冰块受击规则；`ResolveSystem` 仅作为标记为 `Obsolete` 的兼容遗留入口，不接入新主流程。
4. 在 `BoardView` 增加 ice 资源映射；不修改 `MatchFinder`。
5. 在 `CoreTests` 增加底部冰块、分段下落和耐久归零案例。

## 规则入口兼容说明

开发书中的 `ResolveSystem` 是规则结算模块的历史命名。本 Demo 将其职责收敛到 `Core/Rules/MvpRulePipeline.cs`，由 `TurnResolver` 统一调用 `MvpRulePipeline.ResolveSwap` 和 `MvpRulePipeline.ResolveAreaTool`。`Match3Core.cs` 中保留 `ResolveSystem` 仅用于旧固定案例或外部调用的兼容迁移，并使用 `Obsolete` 标记提示迁移；新增规则、测试和表现接入不得直接调用该入口。
