# 架构边界与主流程

本 Demo 沿用一测的架构设计线：Unity 2022.3 LTS + C#，Core 规则可脱离场景运行，表现层只提交命令和消费事件。

## 源码边界

配置资产位于 Assets/Config/LevelConfig_001.asset，由 Config/LevelConfigAsset.cs 转换为纯 C# LevelConfig；棋盘尺寸、颜色、seed、目标、道具和安全上限均从资产进入 Core。

异常处理由 ErrorSnapshot.cs 提供统一契约：记录错误类型、回合号、状态机状态、seed、三路随机游标、事件队列长度和棋盘快照；TurnResolver 保存最近一次规则异常或外部状态错误，ErrorSnapshotExporter 负责输出版本化 JSON。Unity 只提供 `Application.persistentDataPath` 作为导出根目录，不侵入 Core 或规则层。

LevelConfig 统一提供初始生成、连锁、事件队列和洗牌安全上限；规则层不得再使用固定的初始生成尝试次数。

ReplayVerifier 使用 LevelConfig.Clone 创建独立配置副本，不修改调用方持有的关卡配置；摘要一致性比较包含颜色消除统计和最终棋盘。

回合编排层通过 IRulePipeline 依赖规则能力。MvpRulePipelineAdapter 是 MVP 默认实现，测试、未来关卡规则或回放校验可以注入其他实现，而不修改 TurnResolver。

`Core/Diagnostics/TurnPerformanceTrace.cs` 是 `ResolveResult` 的旁路诊断数据，累计匹配、特殊规则、消除、下落补充、洗牌、总逻辑和事件播放耗时。它不进入 `ResolveSummary`、棋盘快照或回放比较；关闭的 EXT 特殊规则保留零值采样项，避免把未执行能力误报为性能结果。

| 模块 | 目录/类型 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 数据模型 | `Core/Match3Core.cs` 中的 `BoardModel`、`Piece`、`Obstacle`、`CellPos` | 保存逻辑状态、快照、恢复 | 访问 Unity 场景或动画 |
| 规则 | `MatchFinder`、`SwapValidator`、`MvpRulePipeline`、`GravitySystem` | 匹配、交换、消除、障碍物、重力、补充 | 读写 `GameObject` |
| 事件 | `Architecture/EventQueue.cs`、`ResolveEvent` | FIFO 排队、上限保护 | 推导规则或修改棋盘 |
| 回合编排 | `Flow/InputController.cs`、`Architecture/TurnResolver.cs`、`Flow/TurnStateMachine.cs` | 管理选择/暂停/终态输入锁，串联命令、规则、事件、目标、回放 | 绘制 UI；直接读取鼠标坐标 |
| 目标/计分 | `Architecture/GoalSystem.cs` | 只读 `ResolveSummary` 和模型结果 | 扫描 View |
| 回放 | `Architecture/ReplayRecord.cs` | 保存规则版本、seed、输入、摘要 | 保存动画状态 |
| 诊断 | `Architecture/ErrorSnapshot.cs`、`ErrorSnapshotExporter.cs` | 捕获上下文、转义并导出版本化 JSON | 修改棋盘；因导出失败阻断状态恢复 |
| 存档 | `Architecture/LocalSaveService.cs` | 保存/加载稳定进度并校验 schema、关卡和配置版本 | 保存动画、暂停、事件队列或临时棋盘；加载失败阻断启动 |
| 结果 UI | `Presentation/ResultPanelModel.cs`、`ResultPanel.cs` | 展示终态、分数、目标进度和剩余步数 | 修改模型；在非 Win/Lose 状态展示结算面板 |
| 性能 | `Core/Diagnostics/TurnPerformanceTrace.cs`、`Presentation/EffectPlayer.cs` | 记录规则阶段与 FIFO 播放耗时 | 参与规则判定或回放一致性比较 |
| 配置 | `Config/LevelConfigAsset.cs` | ScriptableObject → Core 配置 | 把参数散落在表现脚本 |
| 场景/测试入口 | `Presentation/SceneEntryPoint.cs`、`Testing/FixedTestRunner.cs`、`Testing/FixedTestScenario.cs` | 选择 Demo 或固定测试入口；输出固定案例结果 | 修改规则；绕过生产输入/回合编排 |
| 表现 | `Presentation/BoardView.cs`、`EffectPlayer.cs`、`Match3DemoController.cs` | 读取模型、由 `EffectPlayer` 唯一消费 FIFO、暂停/恢复播放、提交命令 | 直接写 `BoardModel`；Controller 直接消费事件 |

## 主流程

当棋盘稳定但不存在合法移动时，MvpRulePipeline 调用 ShuffleSystem。该系统使用独立 ShuffleRandom 执行 Fisher-Yates，最多尝试 LevelConfig.MaxShuffleAttempts 次；仍无解时重建普通糖果布局。洗牌只产生 ShuffleEvent，不触发自动消除、不扣步数、不改变目标进度或障碍物位置。

```text
点击输入
  -> TurnStateMachine.Selecting
  -> TurnResolver.SubmitSwap
  -> SwapValidator
  -> MvpRulePipeline
  -> EventQueue(FIFO)
  -> EffectPlayer 按 FIFO 播放事件 -> BoardView 应用表现
  -> ResolveSummary
  -> GoalSystem + ScoreSystem
  -> Idle / Win / Lose
```

场景入口由 `BootstrapScene`、`GameScene` 和 `TestScene` 分工：Bootstrap/Game 进入生产 Demo，Test 仅启动 `FixedTestRunner`。固定测试场景复用生产 `InputController`、`TurnResolver` 和 FIFO 队列，不另建一套规则实现；场景入口不能修改 Core 状态。

一次操作在 `Resolving/Animating/Refilling/CheckingChain` 期间锁定输入。暂停由 `TurnStateMachine` 保存暂停前状态，`EffectPlayer` 停止协程等待的计时；恢复后回到原状态。Win/Lose 为不可暂停终态。无效交换直接返回，不写入步数、随机流、回放或目标进度。

`Match3DemoController` 只负责将鼠标命中坐标交给 `InputController`、解释输入结果并启动播放器；`InputController` 拥有选择状态和回合编号，通过 `TurnResolver` 提交命令。`EffectPlayer` 是表现事件队列的唯一消费者，按 `LevelConfig.EventDurationSeconds` 顺序播放，每个事件完成后才消费下一个。表现层超出 `MaxTurnWaitSeconds` 时记录 `Presentation` 类型 `ErrorSnapshot`、清空剩余事件并从模型同步视图，随后由 Controller 恢复状态机。

## 扩展示例：新增冰块障碍物

1. 在 `ObstacleType` 追加 `Ice`，不调整已有枚举顺序。
2. 在 `LevelConfigAsset` 增加冰块耐久配置并转换为 `ObstacleDefinition`。
3. 在 `MvpRulePipeline` 的障碍物伤害策略中增加冰块受击规则；`ResolveSystem` 仅作为标记为 `Obsolete` 的兼容遗留入口，不接入新主流程。
4. 在 `BoardView` 增加 ice 资源映射；不修改 `MatchFinder`。
5. 在 `CoreTests` 增加底部冰块、分段下落和耐久归零案例。

## 规则入口兼容说明

开发书中的 `ResolveSystem` 是规则结算模块的历史命名。本 Demo 将其职责收敛到 `Core/Rules/MvpRulePipeline.cs`，由 `TurnResolver` 统一调用 `MvpRulePipeline.ResolveSwap` 和 `MvpRulePipeline.ResolveAreaTool`。`Match3Core.cs` 中保留 `ResolveSystem` 仅用于旧固定案例或外部调用的兼容迁移，并使用 `Obsolete` 标记提示迁移；新增规则、测试和表现接入不得直接调用该入口。
