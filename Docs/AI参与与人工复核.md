# AI 参与、人工复核与误报处理

## AI 参与环节

- 读取一测开发计划并提取模块边界、MVP/EXT 和验收条目。
- 辅助筛选用户提供的图片和字体资源，建立路径及哈希映射。
- 辅助生成固定棋盘测试、架构文档和测试检查清单。
- 辅助执行静态架构检查，包括 Core 是否引用 Unity、Controller 是否绕过 TurnResolver、事件队列是否有上限。

AI 不决定玩法规则，不把生成内容直接作为验收结论。规则以一测计划和规则版本 1.7 为准，代码、资源和测试输出均需人工复核。

## 人工复核方式

1. 对照一测计划核对坐标约定、MVP 开关、输入锁、回滚副作用和事件顺序。
2. 运行 Core、Architecture、Flow、Performance 四个独立测试工程，并使用 UnityCompileTests 编译全部 Unity C# 脚本。
3. 对关键输出核对快照、剩余步数、随机游标、回放摘要和 FIFO 顺序。
4. 对资源逐个检查非空、文件签名、SHA-256、命名映射及实际 Unity Resources 路径。
5. 作者、许可证、商用与署名信息由项目负责人补证并签字；AI 不推断授权。
6. Unity 编辑器可用后补 PlayMode 输入锁、表现同步、终态点击 20 次、Windows 构建和录屏检查。

## 误报处理

- 静态扫描报告“表现层可能写模型”时，人工定位具体写入语句；只有确认发生反向写入才登记缺陷。
- 测试失败时先区分规则回归、测试夹具错误、执行方式错误和环境缺失，修正后必须重新运行相关测试。
- AI 报告的问题只有在固定 seed、固定输入或静态源码位置可复现时才登记为缺陷；无法复现的结论标记为误报，不修改源码和验收结果。
- AI 建议与开发书不一致时，以开发书为准；偏离 Unity/C# 的实现不得进入提交。
- 来源不明或授权不清的图片、字体只作为本次原型资源，不进入商业发布构建。

## AI 任务转工单格式

每个 AI 建议必须转为：任务名称、所属模块、输入数据、实现内容、涉及脚本或配置、验收标准、测试场景、人工校验方式、已知风险。未转工单的建议不得直接合入主分支。
